THE PROBLEM / SCATTERED STORAGE

Passwords are everywhere. The right one is hard to find.

Credentials live across browser autofills, desktop notes, spreadsheets, and memory.

Browser Autofill
Convenient but siloed; accumulates duplicate and outdated logins across different devices.
Notes & Text Files
Completely unencrypted, lacks structure, and offers no auto-fill or search categorization.
Spreadsheets
High security risk, manually updated, frequently desynchronized across machines.
Human Memory
Forces dangerous password reuse and identical variations to survive login friction.
The Daily Friction: When users need a credential, retrieval is painful. Reverting to the familiar shortcut is always faster than learning complex password management rules.
Scattered storage is a rational reaction to high-friction tools 02 / 10

A little help. Your final say.

AI assists with organization and retrieval. You remain completely in control.

TECHNICAL ARCHITECTURE / SECURITY INVARIANTS

A strict boundary between secrets and intelligence.

Redaction is enforced in trusted native code before model inference.

Encrypted Storage
SQLite encrypted via SQLCipher / libsodium. Locking the vault immediately revokes AI metadata access. Search indexes are encrypted at rest.
Trusted Redaction
Redaction is code, not prompt text. Denied: passwords, TOTP seeds, notes, recovery keys, wallet info. Allowed: domains, titles, tags, timestamps.
Sandboxed Runtime
Local llama.cpp process runs in an OS sandbox with no network and read-only filesystem. Zero tools. Outputs validated as strict JSON.
Direct QUIC Sync: Authenticated Syncthing-style transport over UDP. Device ID is the hash of its Ed25519 public key. Pairing via SPAKE2 PAKE.
Disabling AI leaves a completely functional encrypted vault 07 / 10
